# Harness Change

Этот скилл помогает менять сам харнес: правила для агентов, скиллы, процедуры и связи между ними. Результат — применённое изменение, которое остаётся понятным и согласованным с остальными инструкциями.

1. **Определить область.** Понять, какое поведение должно измениться и кому оно нужно. Общие правила держать в корневом `workflow/`, правила одного подпроекта — рядом с ним; продуктовые SDD-артефакты размещать в общей или локальной базе знаний по [карте SDD](../../../KnowledgeBase/SDD/README.md). Перед добавлением нового материала проверить, нет ли уже подходящего владельца или похожей инструкции.
2. **Внести изменение.** Править основной источник, затем обновить относящиеся к нему ссылки в `AGENTS.md`, `CLAUDE.md`, индексах и соседних скиллах. Не копировать одно правило в несколько мест, если достаточно ссылки. При создании, переименовании или удалении скилла синхронно обновить его точки обнаружения для Codex и Claude Code.
3. **Проверить результат.** Применить [Harness Review](../harness-review/SKILL.md) к затронутым файлам. Исправить обнаруженные несоответствия и повторно проверить изменённые места.
4. **Сообщить итог.** Кратко указать, что изменилось, где находится основной источник и какие связанные инструкции обновлены.

## Публикация нового скилла

Создать отдельную папку `workflow/skills/<name>/` с `SKILL.md`, указать в начале `name` и `description`, затем добавить ссылку в [`workflow/README.md`](../../README.md). Чтобы один и тот же скилл обнаруживали оба инструмента, в том же изменении создать **относительные ссылки на папку скилла**:

```text
.agents/skills/<name> -> ../../workflow/skills/<name>  # Codex
.claude/skills/<name> -> ../../workflow/skills/<name>  # Claude Code
```

Для скилла отдельного подпроекта выбрать уникальное в монорепозитории `name` и использовать такой же набор путей внутри него: `<подпроект>/workflow/skills/`, `<подпроект>/.agents/skills/` и `<подпроект>/.claude/skills/`. Такие скиллы Codex обнаруживает при запуске из подпроекта; если скилл должен быть доступен и из корня монорепозитория, добавить там обе ссылки под тем же именем. При переименовании или удалении скилла обновить либо убрать ссылки и упоминания в индексах. Проверить, что ссылки ведут к одному читаемому `SKILL.md` с нужным именем и описанием. Подробность процесса соотносить с реальным риском изменения; не вводить новые обязательные роли, проверки или инструменты без необходимости.
