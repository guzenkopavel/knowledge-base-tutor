# Propose

Прочитайте [ядро SDD](../../sdd.md), [планирование](../../sdd-planning.md) и только относящиеся знания по [индексу](../../../KnowledgeBase/index.md). Найдите действующий контракт по [правилам спецификаций](../../spec-maintenance.md). Если продуктовый смысл ещё неясен, примените необходимые шаги [предварительной проработки](../../product-shaping.md) и продолжите оформление контракта. Если есть рабочий brief, используйте его как источник, а не как принятый контракт; для ясного изменения brief не требуется.

Создайте или продолжите `<KB>/SDD/changes/<имя>/spec.md` в [KB владельца](../../../KnowledgeBase/SDD/README.md) по [шаблону](../../templates/change-spec.md): сохраните источник, актуальные `USR-*`, согласованные изменения, границы, дельту `REQ-*` и наблюдаемую приёмку. Для изменения нескольких подпроектов выберите общий KB. Уточните только неразрешённый продуктовый выбор. `Status: accepted` ставьте после его согласования; если пользователь уже разрешил следующий этап, продолжайте без повторного вопроса.
