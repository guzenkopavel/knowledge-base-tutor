# Project Workflow

1. Прочитайте короткую [точку входа](../../README.md) и определите разрешённую область. По [маршрутизации](../../routing.md) выберите `fast`, `diagnose`, `review` или `design`; явная просьба пользователя главнее автоматического выбора.
2. Для выбранной области прочитайте применимые локальные инструкции, [индекс знаний](../../../KnowledgeBase/index.md) и только нужные документы процесса. До технического решения сверьте действующие требования по [правилам](../../spec-maintenance.md).
3. Для `fast` выполните ограниченную работу без новых артефактов ради процесса. Для `diagnose` используйте [Bug Resolver](../../bug-resolver.md), для `review` — [Code Review](../../code-review.md), для `design` — [SDD](../../sdd.md) и документ текущего этапа.
4. При продолжении выберите явно названный change или единственный подходящий активный план. Восстановите факты и статус из файлов по [правилам контекста](../../context.md); [Ledger](../../ledger.md) учитывайте только при подтверждённой активности. Не выбирайте цель по времени файла. Завершите ближайший разрешённый этап и назовите результат и следующий шаг.
