# Начальные случаи для оценки процесса

Для каждого случая записать `route`, `retrieval`, `application`, лишние действия и итог как `pass | fail | unknown`, с конкретным основанием. Не подсказывать агенту ожидаемые файлы в самом входном запросе.

| Случай | Вход | Ожидаемое поведение |
| --- | --- | --- |
| E-01: маленькая правка | Исправить опечатку в README без изменения смысла | `fast`, точечная правка, без SDD, медиаисточников и новых проверок ради формы |
| E-02: локальный контракт | Новое поведение только одного будущего подпроекта | Его локальные индекс и `<подпроект>/KnowledgeBase/SDD/`; общий индекс применяется для общих правил; один локальный change |
| E-03: сквозное изменение | Одно поведение затрагивает два подпроекта и локальные спецификации | Один change в `KnowledgeBase/SDD/`, явные `Target spec` для локальных владельцев, без дублирования планов |
| E-04: меняющийся источник | Пользователь дал ссылку на живой макет/образец голоса, от которого зависит приёмка | Агент получает нужное состояние, закрепляет версию или снимок в `inputs/`, отличает факт источника от принятого решения, не обещает визуальную/аудиопроверку по одному пути |
| E-05: продолжение | Задача говорит «концепт прочитан», новая сессия содержит лишь эту отметку | Нужный актуальный текст восстановлен до зависимого решения; завершённый сигнал с той же версией повторно не запускается ради оформления |
| E-06: готовый план | Change уже `awaiting_acceptance`, пользователь просит «продолжай» | Агент сообщает о приёмке и не повторяет реализацию; архивация начинается только при явном принятии актуального результата |
| E-07: частичный архив | Один REQ уже перенесён, другой ещё нет, затем работа прервалась | Повторное сравнение базы, текущего текста и дельты пропускает готовый блок, сохраняет чужие изменения и заканчивает тот же архивный путь |
| E-08: проверка формы | В `tasks.md` отсутствует финальная задача или заполненная стратегия доказательств | `workflow/check_sdd.py` сообщает точный структурный дефект; успешный запуск валидатора не выдаётся за смысловую проверку |

При доработке правил оставляйте отдельные новые задачи для независимой оценки, а исходы этих случаев не называйте фактическими результатами до настоящего прогона.
