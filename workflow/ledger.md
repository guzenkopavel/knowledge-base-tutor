# Execution Ledger

Ledger — необязательный пассивный слой длинной агентской работы. Он выводит из завершённых вызовов инструментов ограниченные наблюдения о прочитанных файлах, известных изменениях и выполненных командах. Короткое исполнение остаётся тихим; при накоплении полезного состояния `Inform` возвращает его в контекст, а `Nudge` предупреждает о точном повторе. Ни один из этих сигналов не блокирует работу.

Ledger не является планом, журналом рассуждений, доказательством корректности, подтверждением применения правил или источником статуса задачи. Смысловое состояние остаётся в `tasks.md`, временном bug-файле или review-файле. Успешная сборка или тест не заменяются квитанцией Ledger; повторный запуск допускается по изменившемуся основанию или реальному риску.

## Состав и подключение

- Общее детерминированное состояние и ограниченная политика: `workflow/ledger/ledger_core.py`, `ledger_runtime.py`, `ledger_shell.py`.
- Адаптер Codex: `workflow/ledger/ledger_hook.py`; проектная конфигурация — [`.codex/hooks.json`](../.codex/hooks.json). Он получает `SessionStart` и завершённые `Bash`/`apply_patch` через `PostToolUse`.
- Адаптер Claude Code: `workflow/ledger/ledger_claude_hook.py`; проектная конфигурация — [`.claude/settings.json`](../.claude/settings.json). Он получает `SessionStart` и `PostToolBatch`.

Адаптеры настроены в репозитории, но **конфигурация сама по себе не доказывает запуск**. Codex загружает проектные hooks после доверия к слою `.codex/` и проверки определения hook; Claude Code применяет свои проектные настройки после штатного доверия к проекту. Текущая уже открытая сессия может продолжать работу без новых hooks. Активность в конкретной среде подтверждает только настоящее событие этой среды и появившееся после него состояние или контекст; старый `state.json`, `enabled` и ручная подача JSON этого не доказывают. Если требуется личное подтверждение доверия в интерфейсе, агент просит только это действие и продолжает независимую работу без Ledger. [Документация Codex hooks](https://learn.chatgpt.com/docs/hooks), [документация Claude Code hooks](https://code.claude.com/docs/en/hooks).

Один раз перед первым формальным SDD-этапом или лёгким bug-планом в сессии сообщите статус, если он известен: «Ledger активен» только после подтверждённого события; иначе «адаптер настроен, запуск в этой сессии не подтверждён». Не превращайте статус в запрос разрешения или блокер. Для `fast`, короткого диагноза и самостоятельного ревью отдельный checkpoint не нужен. Явное поручение пользователя подключить Ledger уже даёт разрешение на проектную настройку; повторно спрашивать не нужно.

## Состояние и границы

Хранилище находится в Git directory текущего рабочего дерева: `execution-ledger/state.json`, вне отслеживаемых файлов. Оно ограничено 2 MB и восемью историями `(host, session, agent)`. Содержимое файла или сырой вывод команды не сохраняются; квитанции используют digest, категорию и условие актуальности. Известная запись увеличивает общую ревизию, чтобы наблюдения других владельцев не выдавались за текущие. Неизвестное действие консервативно инвалидирует наблюдения. Ошибка hook, неизвестный payload и повреждённое состояние работают fail-open.

Для Codex `Bash` охватывает и unified `exec_command`, согласно документации hooks. `rtk` и `rtk proxy` распознаются при консервативной классификации команд; точное покрытие содержимого допустимо только для сырого `rtk proxy cat/sed` либо прямого `cat/sed` с подтверждённым полным выводом. Фильтрованный вывод `rtk` не заявляется как полное чтение. `PostToolUse` не доказывает порядок перекрывающихся чтений и записей; поэтому даже свежее наблюдение может иметь статус «прочитано; актуальность не подтверждена». Вызовы вне поддерживаемых hooks могут не наблюдаться.

Механизм не включает автоматический `Reuse`: текущие host-адаптеры не могут доказать безопасную подстановку прежнего результата вместо нового вызова. `Inform` и `Nudge` носят рекомендательный характер.

## Управление

Из корня репозитория `rtk proxy python3 -B workflow/ledger/ledger_hook.py status` показывает локальный маркер и путь состояния. Команды `disable` и `enable` этого же скрипта выключают или включают Ledger в текущем Git worktree, не меняя конфигурацию проекта. Переменная `TUTOR_EXECUTION_LEDGER=0` также выключает его для процесса. Эти действия не подтверждают, что host реально запустил hook.

Изменение адаптеров и их конфигураций проводится через [Harness Change](skills/harness-change/SKILL.md) и проверяется по [Harness Review](skills/harness-review/SKILL.md). Не обходите штатное доверие к проектным hooks и не правьте внутреннее хранилище доверия приложения.
