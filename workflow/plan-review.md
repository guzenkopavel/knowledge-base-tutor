# Сверка плана до реализации

Это завершение планирования SDD или лёгкого bug-плана. Автор плана выполняет одну смысловую сверку перед зависимой реализацией; отдельный агент, задача, отчёт или исполняемая проверка ради неё не нужны.

Сопоставьте актуальный запрос и согласованные изменения, принятый spec/design при наличии, весь план, нужные факты кода, знания и действующие соседние требования. Для bug-плана исходными основаниями служат наблюдение, доказанная причина и разрешённая область исправления. Читайте только отсутствующие или изменившиеся основания.

| Связь | Что проверить |
| --- | --- |
| Запрос → требования или диагноз | Нет потерянного условия, отменённой правки или подмены цели |
| Требования → решение | Существенные случаи и границы обеспечены без противоречия контракту |
| Решение → задачи | Есть нужные изменения, интеграция и результат; нет работы вне разрешённой области |
| Задачи → этап | Перенос принятой дельты в основную спецификацию отложен до archive |
| Задачи → код и знания | Существующие API и факты проверены; создаваемые сущности не представлены как готовые; применимые правила учтены |
| Задачи → зависимости и доказательства | Порядок исполним, результат предпосылки доступен, сигналы выбраны по риску без бессмысленного повторения |

Для `guided` прочитайте каждую задачу глазами исполнителя без истории разговора: один результат, достаточные проверенные решения, нужные материалы и понятная проверка. Для `adaptive` оставьте пространство для локального выбора в пределах принятого контракта. Длинная или рискованная задача требует более глубокой сверки; количество файлов само по себе её не определяет.

Исправьте конкретные несостыковки в документе-владельце и пересмотрите только затронутые связи. Неразрешённый продуктовый выбор верните пользователю. Не переписывайте исходный запрос и не подгоняйте контракт под удобный план. Если блокирующее замечание остаётся, зависимая реализация не начинается. В `tasks.md` либо bug-файле оставьте короткую запись «Сверка плана: готов — ...» или «Сверка плана: нужны изменения — ...». Эта запись не доказывает качество исполнения; сборки, тесты и линтеры в рамках сверки не запускаются.
