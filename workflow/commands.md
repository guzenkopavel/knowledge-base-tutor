# Продолжение SDD и алиасы

Обычная речь — основной интерфейс. Названия скиллов `brainstorming`, `discovery`, `elaborate`, `propose`, `plan`, `implement`, `archive`, `bug-resolver` и `code-review` лишь явно выбирают действие. Первые три задают глубину [предварительной проработки](product-shaping.md); остальные — этап SDD или отдельный маршрут. Сначала определите разрешённую область и текущий этап по артефактам, затем прочитайте только нужный раздел процесса.

## Выбор текущего change

1. Явно названный путь или имя в общем либо локальном `<KB>/SDD/changes/` имеет приоритет. Если одно имя найдено в нескольких KB, уточните путь одним вопросом.
2. Для реализации без имени выбирайте единственный `tasks.md` со `Status: active` во всём рабочем дереве. Изменение `awaiting_acceptance` ожидает приёмки: повторное `implement` не перезапускает финальные проверки.
3. Для архивации без имени выбирайте единственный `awaiting_acceptance`; `active` не подменяет готовый результат. При нескольких кандидатах задайте один узкий вопрос. Время изменения файлов не выбирает change.
4. При переходе к другому незавершённому change сохраните состояние прежнего как `paused`. Возврат восстанавливает `active` с теми же результатами и блокерами, а не начинает работу заново.

`implement <change>/T-*` выполняет одну точную готовую задачу и останавливается. `Execution scope: task` останавливается после следующей готовой задачи, `change` продолжает до готовности либо блокера. Если точная задача — финальная, её положительный вердикт переводит план в `awaiting_acceptance` до остановки. Явное изменение охвата пользователя обновляет сохранённый выбор. Принятые профиль и охват повторно не спрашиваются.

`archive` или однозначное «прими и закрой» выражает приёмку актуального готового результата. Перенос требований выполняется отдельно от реализации; commit, push и публикация не следуют из архивации. Повторная архивация уже закрытого change возвращает существующий путь, не применяет дельту вновь. [Структурный валидатор](check_sdd.py) вызывается в точках, указанных в процессе, без отдельного запуска ради каждой задачи.
